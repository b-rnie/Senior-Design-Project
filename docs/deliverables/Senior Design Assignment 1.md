## **Brand Identity:**

Pet Loop is a video-first pet discovery platform designed to make pet adoption, fostering, and responsible for rehoming more engaging and accessible. The platform allows users to discover adoptable animals through a personalized, scrollable feed featuring short videos and pet profiles. Shelters, rescues, veterinary clinics, and individual pet owners can create profiles for animals that need homes, while potential adopters and fosters can browse, save, and express interest in animals that may be a good fit for them.

## **Logo System:**

The Pet Loop logo combines the project name with a paw, heart, and loop symbol to represent pets, care, and connection. The logo uses the established Pet Loop colors and rounded visual style to create a friendly and recognizable brand identity. It should be used consistently across the application, presentations, marketing materials, and other project content. The logo should not be stretched, rotated, distorted, or recolored outside the approved brand palette.

Color Palette and Typography**

Pet Loop uses a warm, nature-inspired palette centered around Forest Green (#2E5D46; RGB 46, 93, 70) and Warm Cream (#FFF8F0; RGB 255, 248, 240). ## Contribution Guide

The contribution guide shall provide information on the workflow standards of the repo that includes branch naming, procedures for pull requests, requirements of a code review, and how a commit message should be formatted. The GitHub repo also contains a file titled ‘CONTRIBUTING.md’ that includes all the information provided below summarized with instructions on cloning the repo.

## **Branch Naming**

Every editor is expected to create a branch relating to the work that they are adding or editing. The branch name should describe the modification but also be short (if possible). This allows other members to view the title and understand what the branch can add to the main branch and help with clarity.

## **Pull Request Procedures**

After making additions or changes, submitting a pull request is required before the changes may be merged to the main branch. Then, another team member, usually the QA, reviews the pull request and either accepts or comments on the request for further revision. The steps shall be listed below:

1. Team member makes changes inside their local branch.

2. 

<!-- Page break -->
<div style="page-break-after: always;"></div>

Team member commits changes using the written commit message format (listed below) and pushes the branch to the repository.

3. Team member creates a pull request targeting the main branch.

4. The pull request title should relate to the work being implemented by the branch. The description may either be as simple as “See &lt;name&gt;.txt/md” or a few sentences commenting on the changes made that the title may not show.

5. The designated QA team member should examine the changes brought by the pull request and test functionality, as well as designing any test cases, if applicable. This can also be done by any available team member if QA is unavailable.

6. The reviewer may provide any necessary comments or modifications to the request.

7. Once the changes have been reviewed and approved, the branch can be merged into the main branch.

## **Code Review Requirements**

At least one team member separate from the member who submitted the changes and pull request is required to review the pull request before it can be merged to the main branch. The reviewer is responsible for examining the changes, testing possible test cases, and identifying whether the branch can be merged or not.

During the review, the reviewer should ensure that the code is functional, create and verify any test cases, and check that the changes do not create any conflicts with existing code. The reviewer should also provide any comments in the pull request for clarification, modification, corrections, or improvements when necessary.

## **Commit Message Format**

Commit messages should be short while also providing enough information to identify the change, but this can also be overshadowed by the required pull request title and description. With that said, it is still necessary once the branch is merged into the main branch. The message format can be provided in two ways:

Standard way

git add &lt;file-name&gt;

git commit -m "Description of change"

git push -u origin &lt;branch-name&gt;

The editor may also create a .txt or .md file that lists the changes being pushed:

git add .  #or git add &lt;file.name&gt;; git add &lt;changes.txt&gt;

git commit -m "SEE changes.txt FILE"

git push -u origin &lt;branch-name&gt;

When creating the .txt file, the date should be written pertaining to the day the changes are being pushed in the case that the file is being pushed multiple times. Using a file can be helpful in finding and identifying when changes were made and what specifically was changed.

Market Feasibility Analysis

**Existing** **Commercial** **and Open-Source Solutions**

The current market for these apps rely on static based databases like Petfinder, Adopt-a-Pet, etc. These are manual input platforms as well that rely on static filtering for users. Open Source or manual platforms available today are found in groups within Facebook marketplace or other social media platforms like Instagram. Since these are not targeted towards audiences geared for adopting or fostering animals primarily, it can create limited visibility or focus to these animals in need compared to the rest of the app. Additionally, direct competitors like Pawsibly Yours limit the amount of swipes a user has in their customized feed and must wait to refresh to view more animals, along with requiring manual input to add a new animal to the listings.

**Target Audience**

B2B – Consumers that are looking to solve their operational pain points of short staff, limited budget, and time constraints in creating profiles for animals to adopt or for fostering.

B2C – The modern consumption habits of users today like mobile first users, younger generations such as Gen-Z/Millennial, and short form video preference users for fast and easy content consumption.

**Competitor Analysis**

The competitive segment for pet adoption platforms is categorized into three operational models: legacy aggregate databases, vetted marketplace networks, and modern gamified applications. Legacy databases, such as Petfinder and Adopt-a-Pet.com, hold the largest market but rely on outdated web architectures. These have staff involved in data entry process, requiring manually typed biographies and static image uploads, while presenting consumers with rigid, filter-based search mechanics. Vetted networks such as Good Dog offer an alternative by heavily screening responsible breeders and rescues. While providing a highly trusted B2C environment, Good Dog remains a traditional search and static filter platform that is weak in the same backend inefficiencies. Finally, modern applications like Pawsibly Yours have modernized the B2C interface by introducing mobile first, swipe-based mechanics. However, these platforms fail on the B2B backend which continue to rely on manual data entry from shelter staff, which severely limits content supply and causes users to experience limited swipe counts to find animals.

**Value Proposition Mapping**

The market viability of Pet Loop is dominant by mapping its two sided value propositions against existing platforms. On the B2B side, legacy platforms and trusted networks have shelters spend many labor hours manually typing pet bios, Pet Loop provides an AI video intake process. Shelter staff simply upload a raw video, and the platform’s generative AI automatically extracts personality

On the B2C side, where modern swipe-apps fail due to a lack of inventory or limited swipes available for free, Pet Loops automated B2C algorithm provides a plethora of content for users, tailored for users. Project Business Case

**Introduction**

Animal shelters and rescue organizations operate daily under severe resource constraints, chronic staffing shortages and limited assistance while managing a high volume of incoming animals. Currently, these daily operational struggles lack visibility on an easily accessible engagement platform, forcing users to navigate multiple sites to find their local rescue resources. A major contributor to existing problems is the manual data entry required to list animals for adoption, which relies on long written biographies and static filtering forms. This outdated platform format contradicts the needs of modern consumers in 2026, who no longer engage heavily with static image browsing. Instead, users expect dynamic, short-form video content that brings an animal's personality to life for prospective adopters both locally and globally. Pet Loop justifies its development by bridging the gap between animal agencies and prospective fosters or adopters through a two-sided business-to-business-to-consumer (B2B2C) platform (Adobe Experience Cloud Team). Consolidating local rescue networks into a single platform, Pet Loop reduces administrative work using AI video intake and drives community engagement through a fast-paced, swipeable video feed for fosters and adopters.

**Customers &amp; Competitors:**

The target demographic for this platform is two distinct customer segments. Starting with the business-to-business (B2B) demographic consists of non-profit animal rescues and local shelters looking to reduce administrative work and overhead, modernize their digital presence, and increase adoption rates. The second customer segment features the business-to-consumer (B2C) demographic which targets young professionals, university students, and modern consumers who seek a highly visual and engaging way to discover local pets for permanent adoption or temporary fostering. The primary competitors in this space range from large aggregate databases like Petfinder, [Adopt-a-Pet.com](<http://adopt-a-pet.com/>), ASPCA, and Petco Foundation to adopting services like Get Your Pet, Good Dog, AKC Rescue Network, Hearts United for Animals, and Pawsibly Yours (Drew and Gaskin).

**Innovation &amp; Impact:**

The unique aspect of Pet Loop lies in its marketing and video-centric interface, which directly resolves the gaps left by existing market competitors. While apps like Pawsibly Yours have modernized the consumer interface, they rely on traditional, manual data entry on the backend that limit the amount of swipes a user can see on a free plan, defeating the purpose of rehoming animals quickly. This project introduces an AI-automated intake pipeline for the business-to-business (B2B) shelter side. Instead of manually typing biographies and selecting static filters, shelter staff upload a raw, short-form video and photos where generative AI can help to instantly extract behavioral and physical traits such as personality or appearances to auto-generate a comprehensive profile. On the consumer side, the platform replaces static search

<div style="page-break-after: always;"></div>

filters with a behavioral recommendation algorithm. The algorithm dynamically tracks video watch time and swipe interactions to give highly compatible animal matches based on the user. Creating a personalized user experience that adapts to actual user preferences rather than strict breed or age constraints.

The expected ROI and overall impact of this platform are driven by a B2B2C ecosystem. On the B2B side, automating the intake process dramatically reduces administrative labor for shelters. By replacing manual data entry with AI generated profiles, the platform gives back valuable labor hours, allowing underfunded non-profits and more to reallocate valuable staff time directly towards real time animal care. However, the platform's ultimate scalability and financial return are rooted in the B2C user experience. For adopters or fosterers, the shift from a static, filter-based search platform to a personalized, video-centric feed raises the visibility to animals in need of a home. Furthermore, the behavioral recommendation algorithm ensures higher-quality matches between humans and animals, which could potentially increase successful placements and reduce adoption return rates. This highly engaging B2C experience cultivates a large, active user base, opening the floor for future monetization avenues for the platform like targeted affiliate partnerships with pet insurance or food brands whilst browsing.
